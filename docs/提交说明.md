# 比赛源码提交说明

## 提交物

提交 `dist/submission/` 中的 `浙里寻-比赛源码-v3.2.10.zip`。解压后只有一个项目目录，既有可立即打开的离线 HTML，也有可复现该 HTML 和静态网页版的源码。

同名 `.sha256` 是压缩包校验值，可按组委会要求一并提供。源码 ZIP 内的 `文件校验清单.json` 覆盖所有交付文件（不含清单自身）。具体报名表、作品介绍、演示视频和组委会规定的命名格式不在当前源码包中；未假定赛事另有特定模板或大小上限。

## 保留范围

- 应用源码与已经包含的运行依赖。
- 394 项资源目录、详细说明、原始公开文本及来源字段。
- 当前页面实际使用的 5 张图片。
- 构建、打包、导入、启动工具与自动测试；测试数据为虚构示例。
- 使用与开发说明、现有设计规范、运行时来源与原有第三方许可声明。
- 可直接打开的独立 HTML，以及 Mac / Windows 离线快捷入口。

`dist/web/` 可从源码生成，不重复装入源码 ZIP；如组委会需要在线体验，可单独使用该静态产物部署。

## 工作目录与交付包的边界

打包脚本逐项读取固定文件，不遍历整个工作目录。不纳入 `.local/`、模型配置、日志、备份、研究 JSON、截图、旧策划与验收记录、旧审计报告、未使用的参考图片、Git 历史、编辑器目录、系统文件和 `node_modules/`。

开发工作目录可能在 `.local/` 中保存历史归档、更新前备份、模型配置和运行状态；新解压的比赛包不包含这个目录。3.2.1 更新前的比赛源码会保存在原工作目录 `.local/backups/before-3.2.1-20261019/`，供开发者找回。上传时选择生成 ZIP，不要手动压缩整个工作目录。

用户的项目、笔记、收藏、学号备注和附件通常保存在浏览器存储中，构建及打包脚本不读取浏览器配置。同一浏览器打开程序可能读到以前的个人数据，这与 ZIP 内包含数据是两回事。检查初始状态时请使用独立临时浏览器配置。

固定清单能控制文件范围，但不等同于对每个文件内容的永久隐私保证。后续若把私人信息写入已列入清单的源文件、公开数据或 README，仍须在重新打包前检查。不要把 API Key 或研究记录写进源码。

## 来源与身份表述

目录和说明中的资源属于相应机构或提供方，来源保留在数据字段中。内置目录和描述不意味着获得数据库全文许可，也不承诺外部链接实时有效。需要校园权限时，用户在学校或资源方官方页面完成认证。

当前本地账号和学号备注没有经过学校身份核验。本作品不声称已获得学校统一身份接口授权，也不把填写学号标记为已认证在校学生。

第三方运行依赖的原有版权和许可注释保留于 `src/runtime/legacy-vendor.js`，并摘录到 `docs/第三方许可摘录.txt`，运行时来源见 `src/runtime/ORIGIN.txt`。本次整理没有给原创代码或图片另行声明开源授权，也没有改变既有权利归属。
