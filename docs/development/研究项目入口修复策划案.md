# 研究项目入口与研究续接修复策划案

适用项目：浙里寻比赛源码。分析基线：3.2.3。制定日期：2026年10月19日。计划交付版本：3.2.4。

本次修复解决一个具体问题：用户在平台中看到同一组“研究项目”，却不能预判点击后会进入项目管理还是三阶段研究，也难以找到重新进入已有研究的按钮。修复后，“研究项目”继续作为统一的数据单位；工作台负责管理这个项目的资料；研究流程负责推进这个项目的提出问题、分析问题和解决问题。已有项目统一先进入工作台，项目详情始终提供明确的研究入口。

本方案面向项目维护者与验收人员。实施范围为入口、状态判断、必要文案及回归验证，沿用现有星空主题、共享控件和本地保存方式。

## 一 现状和根因

### 1.1 当前数据与界面关系

所有项目都是 `kind: project` 记录。“演示项目：医学影像研究”是一个内置示例项目，不是平台或工作台本身。它带有说明和资料阶段目录，但没有 `researchStage` 字段。

“开启全新研究”调用 `store.startResearch(title)`，创建相同类型的项目，并写入 `researchStage: question` 和 `researchComplete: false`。侧栏加号通过通用编辑器创建普通项目，不附带研究阶段。这两种创建路径具有合理的使用目的：可以先建立资料空间，也可以直接开始研究；问题在于后续入口没有统一处理它们。

源码没有预置名为“12”或“23”的项目。它们作为用户提到的现存项目名称，不作为程序类型、阶段编号或需要清理的测试数据。其实际创建、导入或迁移来源应以当前浏览器的数据为准，不依据名称自动删除或重命名。

### 1.2 已确认的问题

| 编号 | 当前行为 | 原因与影响 | 优先级 |
| --- | --- | --- | --- |
| P01 | 同样点击侧栏项目，有时进工作台，有时进研究页 | `App.openProject` 根据研究阶段和完成标记分支跳转，项目状态改变后入口目标也改变 | 必修 |
| P02 | 普通项目详情没有“开始研究” | `Workspace` 只有在 `researchStage` 存在时才渲染研究按钮，演示项目和普通新建项目缺入口 | 必修 |
| P03 | 已有研究入口不易发现 | “探索模式”实际包含新建和继续两种操作；“继续对话”也不能准确描述离线研究 | 必修 |
| P04 | 工作台阶段页签像是研究导航 | “提出问题／分析问题／解决问题”实际只筛选材料，用户点击后仍留在工作台 | 必修 |
| P05 | 打开普通项目的研究页后，状态可能仍未初始化 | 共享弹窗继续普通项目时直接跳页，`Journey` 用默认阶段显示，项目本身未必记录该阶段 | 必修 |
| P06 | 回看已完成研究可能改变完成状态 | 阶段切换会写入项目；`advanceResearch` 在较早阶段执行时可能把完成标记写回 false | 必修 |
| P07 | 从其他平台页用加号创建项目，完成后仍可能停在原页 | 通用编辑器仅切换项目范围，没有明确进入新项目工作台 | 配套修复 |
| P08 | 指南与实际行为不一致 | 帮助写“侧栏研究项目可直接打开工作台”，代码却有条件跳入研究页 | 配套修复 |

以上依据 `src/app.js` 的 `Workspace`、`App.openProject`、共享探索弹窗回调，`src/research.js` 的 `NewResearchDialog`、`Journey`，以及 `src/core.js` 的 `startResearch`、`advanceResearch`。演示数据来源为已有运行库的 `createLegacyState`。

## 二 修复范围与边界

### 2.1 本次交付

1. 所有已有项目的侧栏入口、工作台项目卡片进入项目工作台。
2. 项目详情始终显示研究操作：开始研究、继续研究或查看研究过程。
3. 统一判断项目的研究状态、阶段和按钮文案。
4. 开始普通项目的研究时初始化原项目，不另建同名项目。
5. 研究页明确返回当前项目工作台；回看完成项目不改写进度。
6. 给工作台的资料阶段筛选添加明确说明。
7. 更新相关帮助、使用指南、交互约定和比赛交付包。
8. 对新旧数据、桌面及窄屏、离线 HTML 和静态网页进行验收。

### 2.2 延续的产品约束

采用现有 React 运行库、共享组件和静态构建，不增加框架或运行依赖。继续使用本机浏览器保存、JSON 手动备份接续；本次不增加云服务器、学校接口、账号认证方式或自动同步服务。在线模型保持可选，离线研究也具有完整的开始与继续入口。

研究的三个阶段、材料种类、任务与日历、目录与收藏、附件及导出能力保持现有范围。已经完成的项目仍可查看和整理资料，本次不新建只读模式、审批流程或“重开研究”业务。用户的项目 ID、标题、关联关系和既有记录必须保留。

## 三 统一概念和入口规则

### 3.1 名称定义

| 名称 | 统一含义 | 界面职责 |
| --- | --- | --- |
| 研究项目 | 用户围绕一个主题建立的资料与研究记录集合 | “12”“23”和演示项目都属于项目 |
| 研究工作台 | 管理当前项目或全部项目的页面 | 项目内容、任务看板、研究日历 |
| 研究流程 | 项目内的三阶段研究页面 | 提出问题、分析问题、解决问题 |
| 资料阶段 | 内容归档与筛选条件 | 仅筛选工作台资料，不承担页面跳转 |
| 研究状态 | 未开始、进行中、已完成 | 决定研究按钮文案，不决定点击项目后跳到哪里 |

### 3.2 入口矩阵

| 用户位置与操作 | 修复后的结果 | 是否创建项目 | 是否写入研究状态 |
| --- | --- | --- | --- |
| 首页点击“开启全新研究”，命名并提交 | 创建新项目并进入提出问题 | 是，一次 | 新项目初始阶段 |
| 首页点击“进入研究平台” | 进入智能选库和平台工具 | 否 | 否 |
| 点击侧栏任意已有项目 | 打开该项目工作台，显示项目内容 | 否 | 否 |
| 点击工作台项目概览卡片 | 打开该项目工作台，显示项目内容 | 否 | 否 |
| 工作台下拉框切换项目 | 切换当前项目内容，保持正在使用的文件夹／看板／日历视图 | 否 | 否 |
| 侧栏加号创建普通项目并保存 | 打开新项目工作台，显示“开始研究” | 是，一次 | 暂不开始研究 |
| 项目详情点击“开始研究” | 在原项目中进入提出问题 | 否 | 初始化原项目，一次 |
| 项目详情点击“继续研究” | 进入该项目已保存的研究阶段 | 否 | 正常项目不写；缺失状态的旧项目按兼容规则补齐 |
| 项目详情点击“查看研究过程” | 打开完成项目已有研究内容 | 否 | 打开与浏览不写进度 |
| 全局按钮“新建或继续研究” | 打开现有共享弹窗，选择新建或已有项目 | 提交新建时才创建 | 与项目详情使用相同规则 |
| 研究页点击“返回项目工作台” | 回到同一项目工作台 | 否 | 否 |
| 完成解决问题 | 标记完成并回到同一项目工作台 | 否 | 写入完成标记 |

侧栏项目和概览卡片打开时复位到项目内容视图。工作台下拉框用于当前工作视图中的项目切换，继续保留看板或日历上下文。两者都进入／停留在工作台，不再根据项目状态跳入研究流程。

### 3.3 主要操作路径

```text
进入研究平台
  → 研究工作台
  → 选择“12”或“23”等已有项目
  → 项目详情中始终存在的研究按钮
      未开始 → 开始研究 → 提出问题
      进行中 → 继续研究 → 上次保存的阶段
      已完成 → 查看研究过程 → 已保存的研究内容
  → 返回项目工作台
```

现有“新建／继续”共享弹窗继续保留。它作为跨项目操作入口，不能成为打开普通项目研究流程的唯一通路。

## 四 状态规则和旧数据兼容

### 4.1 统一状态解析

在 `src/core.js` 提供一个无副作用的状态解析函数，供工作台、项目卡片、共享弹窗和研究页使用。返回状态、有效阶段和阶段名称等界面所需信息，避免每个页面自行判断字段。

| 数据特征 | 显示状态 | 研究按钮 | 进入阶段 |
| --- | --- | --- | --- |
| 完成标记为 true | 已完成 | 查看研究过程 | 有效的已存阶段；缺失时根据研究记录恢复，再无证据时使用解决问题 |
| 有有效研究阶段，未完成 | 进行中 | 继续研究 | 已存阶段 |
| 无有效研究阶段，但存在带阶段的研究对话或选库记录 | 进行中 | 继续研究 | 最近一条有效研究记录所在阶段 |
| 无完成标记、无阶段、无研究活动证据 | 未开始 | 开始研究 | 提出问题 |

研究记录证据仅使用同项目、有效阶段中的研究对话记录或选库记录。普通笔记、材料、收藏和 `data.folders` 目录列表不能证明研究已开始；因此内置演示项目不会因有资料目录就被误判为进行中。

研究阶段合法值保持 `question`、`analysis`、`solution`。优先采用项目有效阶段；仅缺失时才参考研究记录。记录时间使用有效 `updated_at`，否则 `created_at`，仍无有效时间时采用稳定的记录顺序作为兜底。该恢复表示“可接续的位置”，不推断阶段完成比例。

### 4.2 开始已有项目的研究

新增专门的存储操作，例如 `beginResearch(projectId)`，明确区分“创建新的研究项目”与“开始已有项目的研究”：

1. 在操作发生时读取当前账号的最新项目，验证存在且为项目记录。
2. 正常进行中或已完成项目直接返回现有记录；不重建项目，不更新无关时间戳。
3. 无阶段的普通项目在原 `data` 上补齐提出问题和未完成标记。
4. 有历史研究证据的缺字段项目，在用户点击继续时补齐解析出的阶段；保留其他数据。
5. 重复点击对已经初始化的项目不产生额外写入，不产生重复记录。
6. 存储失败时停留原位置并显示现有错误提示，不能先跳页再假装保存成功。

登录、打开工作台、切换项目、浏览项目列表和查看研究内容都不执行批量迁移。保持现有存储键与备份格式，利用可选字段兼容旧数据。

### 4.3 已完成项目的回看

将“当前查看的阶段”和“项目持久化研究阶段”区分处理：进行中的阶段切换继续沿用现有保存行为；已完成项目在页面内切换阶段，只改变当前页面的查看位置。

已完成项目点击页底按钮时按“查看分析问题 → 查看解决问题 → 返回项目工作台”浏览。底层 `advanceResearch` 对已完成项目做保护，不能因回看较早阶段而写回未完成。

打开、切换阶段、返回和再次打开，不改写 `researchComplete`，也不改写原始研究阶段或更新时间。明确的资料编辑仍按现有保存逻辑执行；浏览记录与编辑内容是不同操作。

### 4.4 数字标题和演示空间

“12”“23”作为合法标题继续支持。只检查空白与既有长度限制，不用纯数字名称判断数据是否无效。重名规则沿用原有创建规则，不将两个不同 ID 的项目合并。

演示空间已有的新增项目继续保留。修复不重新播种演示数据，不清空 localStorage 或 IndexedDB，不替用户删除历史项目。代码测试使用隔离的内存或浏览器配置。

## 五 页面与文案调整

### 5.1 项目详情

保留现有项目标题、说明和管理操作，在项目信息区域显示一行轻量状态：“未开始研究”“进行中 · 分析问题”“已完成研究”等。

研究按钮始终显示，作为该项目的主操作。编辑、导出、删除继续使用现有普通或辅助样式，不额外增加整块卡片。研究按钮根据统一状态自动显示开始、继续或查看。

项目概览卡片显示相同状态，帮助用户在选择前判断进度。侧栏继续保持紧凑的项目标题列表，其点击目标统一为工作台。

### 5.2 平台全局研究入口

“探索模式”更名为“新建或继续研究”。共享弹窗保留“继续已有项目”和“开启全新研究”两种方式，默认选择逻辑沿用现有行为；已有项目选择后显示其状态，提交按钮使用对应的开始、继续或查看文案。

没有项目时默认新建，已有项目选项保持禁用。取消、关闭、Escape 沿用现有 dialog 焦点恢复，不产生记录。

### 5.3 资料筛选和返回

工作台阶段标签前显示“资料阶段”，并设置分组的可访问名称；选中的筛选按钮具有 `aria-pressed` 状态。保留现有四项筛选和资料归属规则，不把这些页签变成研究跳转入口。

研究页返回按钮统一为“返回项目工作台”。研究页面找不到所选项目时提供返回工作台的恢复入口，不自动新建替代项目。

### 5.4 视觉和响应式

复用 3.2.3 已统一的控件：桌面常规 40px、辅助 32px，手机共享按钮至少 44px。主研究操作使用现有紫色按钮；状态用文本或轻量标记，不引入新的高饱和色。

长项目名允许合理截断或换行；状态和研究操作不能被挤出可视区域。窄屏项目的研究主按钮单独占一行，编辑、导出、删除在下一行；“资料阶段”说明单列一行，四个筛选按钮等宽排列。已选项目时，全局“新建或继续研究”使用次级样式，突出当前项目的研究主操作。查看 390、862、1183、1440 像素宽度下的布局，并补充更窄宽度的溢出检查。
