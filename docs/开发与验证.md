# 开发与验证

## 开发环境与源码职责

构建、打包、核心测试和可选本机服务要求 Node.js 22 或更新版本。日常运行依赖已保存在 `src/runtime/legacy-vendor.js`，核心命令不下载 npm 包，不需要 `node_modules/`。

| 路径 | 职责 |
| --- | --- |
| `src/core.js` | 本地账号、记录、检索、备份、导入冲突处理与草稿 |
| `src/extensions.js` | IndexedDB 附件、带原件的 JSON 转移、可选模型桥接 |
| `src/components.js` | 共享表单、弹窗、资源卡、资料编辑 |
| `src/research.js` | 三阶段研究流程与对话 |
| `src/app.js` | 应用入口、导航、工作台和设置 |
| `src/styles.css` | 全站主题与响应式样式 |
| `src/data/` | 应用使用的公开资源目录及规范化说明 |
| `src/data/source/descriptions.json` | 394 篇说明的原始公开文本与来源，供维护和再导入 |
| `src/runtime/` | 原有浏览器运行依赖及来源记录 |
| `style/` | 实际被应用引用的图片 |
| `scripts/` | 构建、静态站点、数据导入、提交打包和可选本机服务 |

原始说明与规范化说明是同一导入链路的输入和输出，不要任意删掉其中一份。更新原始说明后，在根目录运行 `npm run import-descriptions`，检查导入报告，再运行测试和构建。导入脚本检查全部 ID、名称、三段结构、来源 URL 与正文长度；`src/data/descriptions-manifest.json` 记录原始资料哈希和导入摘要。它不表示外部网站实时可访问。

视觉规范位于 `docs/development/DESIGN.md`，交互约定位于 `docs/development/UX-CONTRACT.md`。3.2.1 保留业务功能和视觉方案，修复附件导入、异步下载和静态更新的边界问题，并减少离线文件中重复的图片数据。

## 构建与源码调试

```sh
npm run build
```

构建输出两个产物：

- 根目录 `浙里寻-独立网页版.html`：嵌入运行代码、数据及图片，可以离线打开。每张图片仅保存一份，页面启动时在 head 内还原原有 CSS，避免重复大图和浏览器自定义属性长度限制。
- `dist/web/`：分离文件的静态站点，含应用清单、离线缓存与主动更新提示，支持子目录部署。

`dist/web/` 是纯生成目录，每次构建会先清理再生成；不要放个人文件或手工修改后的唯一副本。不要直接编辑生成的 HTML；修改 `src/`、`style/` 或构建脚本后重新构建。

`npm start` 会先构建再以前台模式启动本机服务；首页读取构建 HTML，`http://127.0.0.1:4173/dev` 直接加载源码。`npm run open` 后台启动，`npm run stop` 停止当前目录管理的服务。普通离线运行与比赛快速体验均不需要本机服务。

## 自动测试

```sh
npm test
```

包含核心数据、账号隔离、导入冲突、草稿、附件、本机模型接口、启动器和提交打包检查。接口测试使用本地模拟服务，测试账号与资料为虚构内容，不使用真实 API Key 或用户浏览器配置。

接口及启动器测试会临时监听 `127.0.0.1` 端口，受限执行环境需允许本地网络监听。Windows 的符号链接拒绝测试会跳过，其余测试应正常执行。仅运行不监听端口的测试可使用：

```sh
node --test tests/core.test.cjs tests/extensions.test.cjs tests/package.test.cjs
```

## 可选真实浏览器回归

维护环境需已有 Playwright 与可用的 Chromium 系浏览器。测试依赖没有纳入应用运行依赖，普通评审不需要安装。让 Node 能解析 `playwright` 模块后，运行：

```sh
node tests/browser-smoke.cjs
node tests/lightweight-browser.cjs
```

可用 `ZLX_BROWSER_PATH` 环境变量指定浏览器可执行文件，或使用 Playwright 已安装的 Chromium。测试使用临时浏览器配置与临时服务，不读取用户日常浏览器记录；外部 HTTP 请求被测试拦截。

第一组覆盖构建 HTML、源码入口、本地文件入口、独立标签页、资料弹窗、真实附件备份、离线匹配及研究完成，也验证正常 Word / 附件下载与退出账号后的下载取消。第二组覆盖窄屏草稿恢复、阶段隔离、缩小可视高度、完整项目下载、重复导入、子目录部署、断网重载和确认后更新。截图只生成在系统临时目录，不进入提交包。

## 比赛打包与复验

```sh
npm run package
```

脚本先重新构建，再按 `scripts/package.mjs` 中的逐文件白名单压缩，输出 `dist/submission/浙里寻-比赛源码-v3.2.10.zip` 及同名 `.sha256`。ZIP 含源码、说明、测试、必要素材与可运行 HTML；不重复包含可重建的 `dist/web/`。添加新源码文件时，需要同步维护白名单。

包内生成 `文件校验清单.json`，同时更新工作目录的同名清单。固定 ZIP 时间戳和统一权限用于减少无关元数据，时间戳不表示文件开发日期；Mac `.command` 的可执行位会保留。不写入文件所有者、扩展属性或资源分叉。

把 ZIP 解压到新目录后，按以下顺序验证：

```sh
npm run verify
npm test
npm run build
```

`verify` 检查清单范围和 SHA-256；不检查用户随后新增的文件，也不替代功能测试。验证结果取决于实际运行环境，不要把哈希通过当作跨平台兼容性结论。
